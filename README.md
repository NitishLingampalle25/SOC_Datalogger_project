Secure RISC-V SoC Data Logger for Mission-Critical Telemetry (Kavach / TCAS)MAIN MOTIVATION OF THE PROJECT

Modern safety-critical transportation and cyber-physical systems, such as the Indian Railways Train Collision Avoidance System (TCAS / Kavach), require continuous, real-time logging of mission-critical telemetry. Crucial operational variables—including train speed, signal aspects, brake pipe pressure, braking commands, and driver inputs—must be recorded to support incident forensics, regulatory compliance, and post-accident investigations. In high-throughput industrial environments, handling continuous incoming sensor streams purely via software places an unsustainable burden on the primary processor pipeline. Repeated interrupt servicing, software-driven memory copy routines, and cryptographic algorithms introduce severe CPU pipeline stalls, jitter, and the risk of unrecorded telemetry bursts. Furthermore, telemetry stored without hardware-level cryptographic isolation is susceptible to tampering, while bus deadlocks or firmware hangs can lead to unmonitored failures. The primary motivation of this project is to architect a specialized System-on-Chip (SoC) subsystem that offloads memory transfers, cryptographic data protection, and execution health tracking directly to dedicated hardware peripherals. By offloading these tasks to autonomous hardware blocks, the system achieves zero telemetry data loss, constant-time cryptographic protection, and autonomous fault isolation without degrading the performance of the control processor.  

 SYSTEM INTELLECTUAL PROPERTIES (IPS) AND JUSTIFICATION : 

A total of six core Intellectual Property (IP) blocks are integrated into the SoC architecture to deliver this functionality. These comprise three mandatory baseline processing elements alongside three purpose-selected peripherals chosen to optimize data ingest, arbitration fairness, and fail-safe recovery.   

MANDATORY IPSRISC-V Processor Core (VeeR EL2)

The Western Digital VeeR EL2 core is an open-source, dual-issue 32-bit RISC-V processor implementing the RV32IMC instruction set architecture. It serves as the primary control-plane master for the entire subsystem. The core incorporates a dedicated 32 KB Instruction Closely Coupled Memory (ICCM) and a 64 KB Data Closely Coupled Memory (DCCM). 

The VeeR EL2 was selected because its closely coupled memories allow control loops, interrupt handlers, and mission-critical routines to run with deterministic, single-cycle latency without contending for the external system bus. The processor configures peripheral memory-mapped registers, monitors system status, handles top-level alerts, and processes fault vectors while the remaining telemetry pipeline operates autonomously in hardware.  
Dual-Master AXI4-Lite Interconnect Matrix
The central communication backplane is a dual-master AXI4-Lite interconnect matrix configured with crossbar routing and dedicated round-robin arbitration logic. The interconnect arbitrates system bus access between Master 1 (the RISC-V Core) and Master 2 (the Bus-Mastering DMA Controller) across twelve slave address ranges. An AXI4-Lite implementation was chosen to maintain low area overhead and timing closure while retaining standardized, robust handshaking across independent write and read address, data, and response channels. The integrated round-robin arbiter enforces transaction-boundary locking and fair bandwidth allocation, preventing continuous sensor data traffic from starving the RISC-V core of access to memory-mapped control registers.   Hardware AES Cryptographic Accelerator

The hardware AES accelerator is an AXI4-Lite slave IP dedicated to executing cryptographic encryption and decryption operations over staged sensor payload blocks. It natively supports both 128-bit and 256-bit key modes across Electronic Codebook (ECB) and Cipher Block Chaining (CBC) configurations. Implementing AES acceleration directly in hardware eliminates the heavy computational latency and software overhead of algorithmic encryption. It also avoids data cache lookup-table timing side-channel vulnerabilities through a hardware-level execution path. The engine features direct memory access to staging storage and auto-kicks system supervisor lines upon finishing block transmutation to signal pipeline liveness.   


PROJECT-SPECIFIC SELECTED IPSBus-Mastering DMA Controller (Master 2 and Slave)
The Direct Memory Access (DMA) controller is a dual-interface block functioning as an AXI4-Lite slave for CPU configuration and an AXI4-Lite master for autonomous memory movement. It features dedicated hardware handshaking lines connected directly to external telemetry ingest buffers. The DMA controller was integrated to eliminate CPU-driven programmatic I/O polling and memory-copy loops. When sensor buffers hit programmed thresholds, the DMA requests the AXI bus, transfers telemetry packets directly into staging memory, and automatically issues a hardware synchronization pulse upon transfer completion to trigger downstream processing without processor intervention.   32 KB Dual-Port Staging SRAM
The staging memory is a dedicated 32 KB dual-port SRAM subsystem structured to decouple streaming ingest from cryptographic operations. Port A of the SRAM is routed exclusively to the AES Engine datapath for reading cleartext blocks and committing ciphertext results. Port B is exposed across the AXI4-Lite interconnect matrix, enabling concurrent access by the DMA controller during sensor ingestion or by the CPU for diagnostic verification. Dedicated dual-port staging prevents memory contention and eliminates system bus congestion by isolating continuous cryptographic read/write traffic onto a private hardware port.   Fault-Tolerant System Watchdog Timer (WDT)
The Watchdog Timer is an autonomous supervisor peripheral that tracks execution states and hardware handshaking lines completely independent of software control. It features a down-counter clocked by a dedicated peripheral reference, an early-warning interrupt threshold, a Non-Maskable Interrupt (NMI) line, and a hard CPU/SoC reset output line. It was specifically selected to provide autonomous fail-safe recovery in safety-critical rail environments. A hardware input pin on the WDT is wired directly to the AES completion pulse, creating an automated hardware keepalive loop. If sensor ingestion fails, the DMA hangs, or the cryptographic core encounters a deadlock, the watchdog counter expires, instantly asserting CPU_NMI or triggering a system reset to bring the train logger back to a known safe state.   KEY ARCHITECTURAL AND IMPLEMENTATION FEATURESHardware-Synchronized Autonomous Pipeline: The telemetry logging loop is fully interlocked via dedicated hardware handshaking signals. The UART asserts a direct request to the DMA; the DMA fills Port B of the Dual-Port Staging SRAM and triggers a completion pulse; the AES engine processes the block via Port A; and the AES engine asserts a single-cycle done pulse that automatically resets the Watchdog Timer. This autonomous chain runs continuously without software intervention.   Zero-Starvation Arbiter Guarantees: The AXI4-Lite arbiter tracks bus state using an alternating pointer. Because arbitration decisions execute at transaction boundaries, high-frequency DMA write bursts cannot monopolize the bus. The RISC-V core is guaranteed access to memory-mapped registers within bounded clock cycles.   Non-Blocking CPU Execution: When the DMA controller is actively driving transactions on the AXI bus, the RISC-V core does not stall unless it initiates an off-chip AXI transaction. By executing instructions from its 32 KB ICCM and managing variables inside its 64 KB DCCM, the core continues operating at full clock frequency during heavy bus transfers.   Privilege and Bus Protection Guards: The interconnect address decoder strictly enforces privilege rules and access permissions. Master 2 (DMA) is blocked by hardware firewalls from accessing sensitive registers reserved for Master 1 (CPU), such as the AES encryption key registers and the Watchdog control registers. Non-aligned 32-bit accesses automatically return slave error (SLVERR) responses to prevent payload memory corruption.   Comprehensive Fault and Interrupt Handling: The architecture incorporates an on-chip Programmable Interrupt Controller (PIC) that aggregates priority-encoded interrupts from the DMA, AES core, UART, and Watchdog early warning lines, routing clean vectored interrupts to the processor. Fatal failures bypass interrupt masking entirely via dedicated Watchdog lines wired directly to the CPU Non-Maskable Interrupt and system reset pins.
